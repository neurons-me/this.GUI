# Beatle — NRP Algebraic Expression Contract

> **Beatle parses intent. NRP resolves route. `.me` resolves meaning.**

---

## What Cleaker is

A namespace has two modes of existence, and they are not in conflict — they are complementary:

**Mode 1 — Direct navigation.** The namespace is the URL.

```
https://jabellae.cleaker.me/photos
```

You navigate to it. The monad serves the view. The browser renders it. This is a normal HTTPS request: the `Host` header carries the namespace, the path carries the semantic address. No special client needed.

**Mode 2 — Parallel correlation.** You are anywhere on the web, and your namespace travels with you.

```
browser:  https://wikipedia.com/Scarab      ← normal HTTP, any site
Beatle:   me://cleaker.me/jabellae          ← WebSocket, your namespace
```

Beatle holds the channel open. Your identity is present. The browser URL does not change — but your namespace context is active. You can combine both: your data from `jabellae.cleaker.me` overlaid on the page you are viewing.

This is what `@ surface` expresses in the algebra:

```txt
jabellae @ wikipedia.com
```

Not a redirect. Not a navigation. A correlation — your namespace data, projected onto where you already are.

**The response format follows the channel:**

| Channel | Trigger | Response | For |
|---|---|---|---|
| HTTPS | URL / link | HTML view (rendered by monad) | human navigation |
| Beatle WS | `nrp.open` | JSON `resolved` + `data` | system composition |

Same namespace. Same path. Same meaning. Different representation based on how you asked.

---

## Beatle's role

Beatle is the client of the second channel. It is not a navigation widget — it opens a **bidirectional WebSocket** to a `.me` namespace and keeps it alive while the browser does whatever it does via HTTP.

---

## NRP URI Shape

Beatle separates the NRP address from the algebraic expression that runs inside it.

```txt
me://<namespace>[<monad-selector>]/<expression>
```

| Slot | Meaning |
|---|---|
| `namespace` | Semantic parent space, e.g. `cleaker.me` |
| `[monad-selector]` | Optional technical execution override |
| `expression` | Algebra resolved relative to the namespace |

The canonical form omits the selector:

```txt
me://cleaker.me/jabellae + alex
```

NRP chooses the execution route through Total Monad Synthesis. A selector only appears when the caller needs a technical override:

```txt
me://cleaker.me[monadlisa]/jabellae + alex
me://cleaker.me[current]/profile.name
me://cleaker.me[]/jabellae + alex
```

`[iphone]`, `[macbook]`, and `[local]` are not canonical selectors unless those are actual monad names. In NRP v0.2.1, physical targets such as `iphone` live as NetGet placement metadata on a monad. `[surface:name]` is legacy compatibility from earlier drafts; new implementations should prefer monad selectors.

This is separate from the `@` operator below. `[...]` chooses or constrains the executor. `@` chooses the projection/overlay surface of the result.

## The Grammar

```txt
expr    = term ('+' term)*           // union
term    = factor ('∩' factor)*       // intersection
factor  = atom ('@' overlaySurface)? // projection overlay
atom    = '~' atom                   // complement
        | '(' expr ')'              // grouping
        | NAMESPACE                  // leaf (Cleaker-parsed)

overlaySurface = '"' URI '"'        // quoted URI
               | NS_TOKEN           // bare hostname
```

### Operator Precedence

| Operator | Symbol | Binding | Precedence |
|---|---|---|---|
| Complement | `~` | prefix | highest |
| Overlay | `@` | postfix | 3 |
| Intersection | `∩` | infix | 2 |
| Union | `+` | infix | 1 (lowest) |

All binary operators are **left-associative**. Use parentheses to override.

## Expression Examples

### Relative handle

```txt
jabellae
```

Resolve `jabellae` relative to the active parent namespace selected by Beatle's resolver, for example `cleaker.me`.

### Union — shared channel

```txt
jabellae + alex
```

Both `jabellae` and `alex` are in the channel. The NRP server resolves the union and returns the combined audience.

### Intersection — shared region only

```txt
jabellae ∩ team.acme
```

Only the overlapping region of both namespaces. The channel represents what both parties have in common.

### Complement

```txt
~jabellae
```

The complement of the `jabellae` namespace. In a filter context: everything except `jabellae`.

### Overlay — expression over a projection surface

```txt
jabellae @ wikipedia.com
```

Open the `jabellae` channel projected over the `wikipedia.com` overlay surface. The browser keeps its own HTTP connection to Wikipedia — Beatle adds a parallel namespace session.

### Quoted URI overlay

```txt
jabellae @ "https://wikipedia.com/Scarab"
```

Full URI as overlay surface. Must be quoted. Bare tokens are hostname-only.

### Compound expressions

```txt
jabellae + alex @ wikipedia.com
```

⚠️ This parses as `jabellae + (alex @ wikipedia.com)` — overlay applies to `alex` only.

To overlay the union:
```txt
(jabellae + alex) @ wikipedia.com
```

```txt
jabellae ∩ (team + friends) @ wikipedia.com
```

Intersection of `jabellae` with `(team ∪ friends)`, overlaid on `wikipedia.com`.

### Nested complement

```txt
~(public + spam)
```

Complement of the union. The parentheses are required — without them, `~public + spam` = `(~public) + spam`.

### Full Cleaker namespace token

```txt
cleaker.me[host:localhost|protocol:http|port:8161]:open/profile
```

A Cleaker-format namespace leaf with context, operation, and path. The parser accepts the full Cleaker grammar for individual namespace tokens.

In NRP v0.2.1, bracket selectors inside a full `me://` URI are monad selectors, not UI surfaces:

```txt
me://cleaker.me[monadlisa]/profile
```

`monadlisa` is a monad execution route. A device like `iphone` belongs in the monad placement index unless it is deliberately registered as a monad name.

## Canonical Form

The parser produces a `canonical` string that is **semantically stable** across parse/serialize round-trips.

```txt
Input:     a ∩ (b + c)
Canonical: a ∩ (b + c)   ✓

Input:     ~(a + b)
Canonical: ~(a + b)      ✓

Without parenthesization:
  a ∩ b + c  →  parses as  (a ∩ b) + c  ≠  a ∩ (b + c)
```

The client sends `{ raw, canonical, ast }` over the wire. The **server re-parses `canonical` independently** — it does not trust the client AST. `canonical` is the agreed contract.

---

## Validity

Every parsed expression carries two flags:

| Flag | Meaning |
|---|---|
| `syntaxValid` | Algebra structure is correct — safe to send |
| `namespaceValid` | All leaves passed Cleaker validation |

`valid = syntaxValid`. An expression can be `valid: true` but `namespaceValid: false` — the server resolves against the real `.me` kernel and has final authority.

---

## State Machine

```txt
idle
  ↓ open(expression)
parsing       local NRP algebra parse
  ↓
connecting    WebSocket transport handshake
  ↓
resolving     NRP semantic handshake (server re-parses canonical)
  ↓
connected     channelId, endpoints, audience, capabilities, disclosure
  ↓
streaming     server pushing live updates
  ↓
disconnected  channel closed cleanly
  ↘
error         parse error, connection refused, or resolution failed
```

## Wire Contract

### Client → Server: `nrp.open`

```ts
{
  type: 'nrp.open',
  expression: string,     // raw input
  canonical: string,      // normalized, precedence-correct
  ast: NRPNode,           // hint — server must re-verify
  client: {
    surface?: string,     // current browser/projection surface, not the NRP [monad] selector
    userAgent?: string,
    gui: 'Beatle'
  },
  timestamp: number
}
```

### Server → Client: `resolved`

```ts
{
  type: 'resolved',
  channelId: string,
  payload: {
    endpoints: string[],
    audience?: string[],
    capabilities?: string[],
    surface?: string,     // resolved overlay/projection surface, if any
    disclosure: 'public' | 'closed' | 'stealth' | 'contested'
  },
  timestamp: number
}
```

### Bidirectional: `data`

```ts
{ type: 'data', channelId?, payload: unknown, timestamp: number }
```

### Server → Client: `stream`

```ts
{ type: 'stream', channelId?, payload?: unknown, timestamp: number }
```

### Server → Client: `error`

```ts
{ type: 'error', channelId?, payload: string, timestamp: number }
```

---

## Disclosure Levels

The server returns a `disclosure` level based on what the `.me` kernel reveals:

| Level | Meaning |
|---|---|
| `public` | Namespace is readable, endpoints available |
| `closed` | Namespace exists, caller has no access |
| `stealth` | Namespace does not reveal its own existence (A0/A2 axioms) |
| `contested` | Multiple conflicting monads claim this namespace |

`stealth` is structural — the `.me` kernel never confirms existence of a secret scope root. Do not show existence hints to the user when `disclosure === 'stealth'`.

---

## Authority Model

```txt
Client (Beatle)       → parses intent, sends hint
NRP server            → re-parses canonical, resolves route
.me kernel (server)   → resolves meaning: secrets, audience, capabilities
```

The client never has semantic authority. It formats and presents. The kernel decides.

---

## useBeatle API

```ts
const { channel, open, send, disconnect } = useBeatle(nrpEndpoint?, onMessage?);

open('jabellae + alex @ wikipedia.com');  // parse → connect → resolve
send({ type: 'annotation', text: '...' }); // only when connected or streaming
disconnect();                              // close cleanly
```

`channel` is a `NamespaceChannel`:

```ts
{
  expression,    // NRPExpression (raw, canonical, ast, syntaxValid, namespaceValid)
  resolved,      // string[] — endpoint URLs
  state,         // ResolutionState
  channelId,     // string
  audience,      // string[]
  capabilities,  // string[]
  surface,       // string (from @ operator)
  disclosure,    // NRPDisclosure
  error          // string
}
```
